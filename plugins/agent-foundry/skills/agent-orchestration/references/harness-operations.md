# Harness operations

Discover the callable tools and current schemas. Prefer native delegates for in-session subtasks; use exact IDs, completion events, and bounded waits. A user-visible chat is not an internal delegate: create or message chats only under explicit user authorization. Preserve scope, model/effort, input revision, and approval rules in every assignment.

Inspect attached artifacts before creating managed worktrees; pin the returned path. Worktree creation does not move the caller automatically. Keep one decision owner and reuse specialists; a role's model field does not justify another decision agent.

For quota, use the supported official harness source if exposed. Used percentage means consumed capacity; missing measurements remain unknown. Do not read credential files, install dashboards, combine accounts, or silently switch billing providers.

External CLI/harness delegation requires an explicitly authorized route and actual installed capability. A busy native slot is not permission to launch an external agent. Discover current CLI help and provider configuration; never bypass permissions, install another harness, or assume a background scheduler.

Record the exact session/process ID and pending tool state. Quiet logs are not termination evidence. Never resume by newest session or replace a writer that might still run. Resume only a proven saved ID; retry only after a changed condition with a bounded budget and retained partial-work inspection.

If completion cannot be observed, retain the assignment and report that automatic continuation is not armed. Do not create recurring monitors or alter sleep settings to keep work alive.
